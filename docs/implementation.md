# 첫 구현 안내

## 범위

`src/ledger.js`는 분개 검증, 잔액·재무상태표·기간 손익·현금 증감을 계산하는 순수 함수입니다. 금액은 원 단위 정수(KRW)를 사용합니다. `src/book.js`는 Node.js 내장 SQLite에 계정, 확정 분개, 카드 할부 계획, 조정 배치를 저장합니다.

계좌 그룹(자산·부채)은 계좌 목록을 묶고, 예산 카테고리(식비 등)는 거래 지출을 묶습니다. `onBudget` 계좌의 자산 잔액에서 카드 등의 부채 잔액을 뺀 값을 가용 자금으로 계산합니다. 월별 예산 배정액은 덮어쓰기로 수정할 수 있고, 미사용액은 다음 달로 이월됩니다. 거래의 `budgetAllocations`는 비용 분개 합계와 일치해야 하며, 카드를 나중에 결제할 때는 예산 지출이 새로 생기지 않습니다. 온버짓 계좌에서 오프버짓 계좌로의 이체는 가용 자금만 바꾸며 소비로 분류하지 않습니다.

`src/amount-expression.js`의 `calculateAmount`는 숫자 입력칸용 사칙연산과 괄호를 계산합니다. 최대 여섯 자리 소수를 읽고 정수 원으로 반올림(정확히 절반이면 0에서 멀어지는 방향)합니다. 변수·함수·셀 참조와 JavaScript 코드는 허용하지 않습니다.

`src/imports.js`와 `src/import-api.js`는 요청 중복 검사, 원문 검토 대기함, 인증된 상태 조회를 제공합니다. 현재 공개 엔드포인트는 API 키와 계정 키를 함께 사용하는 `/api/v1/push-events`입니다. 키 원문은 발급 시에만 반환하고 데이터베이스에는 SHA-256 다이제스트만 저장합니다. 32바이트의 무작위 키를 사용합니다. 사용법은 [수신 API 안내](import-api.md)를 참고하세요.

새로운 `src/push-credentials.js`, `src/push-parser.js`, `src/regex-worker.js`는 Pocket ID 사용자 `sub`에 묶인 API 키와 계정 키, 계정별 필드 정규식, 시간 제한 파싱을 제공합니다. `src/oidc-auth.js`는 OIDC 인증 코드+PKCE, state/nonce, 사용자 세션을 관리하고 `src/admin-ui.js`는 정규식 편집·시험, 가족 접근 권한, 수신 검토 페이지를 제공합니다. `src/review.js`는 원문을 승인 분개에 연결하고 하나의 DB 트랜잭션으로 반영합니다. 실제 Pocket ID 접속은 배포 환경에서 검증해야 합니다.

`src/manual.js`는 소유자 전용 계좌 그룹·계좌·예산 카테고리 등록과 권한이 적용된 단순 거래 입력·계좌 조회를 제공합니다. `/admin/accounts`에서 항목을 등록하고 `/admin/register`에서 지출·수입·이체·기초 잔액을 한 건씩 입력합니다. `manual:<requestId>`로 중복 제출을 방지합니다. `/admin/budget`에서 소유자는 월별 예산 배정액과 이월 잔액을 조회·변경합니다. `/admin/reports`에서 소유자는 장부 전체 잔액·기간 손익·현금 증감을 보고, 가족 구성원은 허용된 계좌 잔액만 조회합니다.

`src/report-details.js`는 소유자 전용 상세 보고서를 구성합니다. 재무상태표는 기준일 계정별 잔액과 자산·부채·순자산 및 누적 손익을, 손익계산서는 기간 수입·비용과 순손익을 보여 줍니다. 현금흐름 내역은 현금성 계좌별 기초·입금·출금·기말과 원거래를 표시하고 원장 순증감과 일치하는지 검증합니다. 현금성 계좌 사이의 이체는 두 계좌에 각각 입금·출금으로 표시되지만 전체 순증감은 0입니다. 계정별 원거래에서는 차변·대변과 정상잔액 방향의 증감을 확인할 수 있습니다. 가족 구성원은 통합 내역에 접근할 수 없습니다.

`src/backups.js`는 `BUDGETBOOK_BACKUP_DIR` 절대 경로에 SQLite 온라인 백업을 생성합니다. 임시 파일을 완성한 뒤 `PRAGMA integrity_check`로 검사하고 최종 파일명으로 이동합니다. 기본 백업 주기는 1일이고 보관 수는 30개이며 서버 시작 시와 매시간 만기 여부를 검사합니다. 소유자는 `/admin/backups`에서 주기·보관 수를 변경하거나 즉시 백업할 수 있습니다. 복구는 서버를 중지하고 백업 SQLite 파일을 `BUDGETBOOK_DB` 위치에 복사한 뒤 다시 시작하는 서버 관리자 작업입니다. 백업 경로에는 DB와 별도로 영속 볼륨을 사용해야 합니다. Google Drive 업로드·백업 암호화·앱 화면 복구는 아직 없습니다.

`Dockerfile`과 `compose.yaml`은 NAS에 앱을 배포하는 초기 예시입니다. 호스트의 `data`와 `backups`를 서로 다른 영속 경로로 연결하고 로컬 호스트 포트를 통한 HTTPS 역방향 프록시를 전제합니다. `/healthz`는 DB 질의 성공 여부만 `204`로 알리고 장부 내용을 공개하지 않습니다. 실제 NAS에서의 이미지 빌드, UID/GID 권한, Pocket ID 접속은 배포 환경에서 검증해야 합니다. 절차는 [NAS 배포 안내](nas-deployment.md)에 있습니다.

`public/`과 `src/local-sync.js`는 설치형 PWA의 초기 범위입니다. 앱 셸은 서비스 워커가 캐시하고 사용자별 계좌·최근 거래 스냅샷과 단순 거래·다중 행 분할 거래·분할 거래 수정 대기열은 기기 잠금 암호로 암호화해 IndexedDB에 저장합니다. 온라인 복귀 시 OIDC 세션과 CSRF를 확인한 뒤 기존 `recordManual`/`recordSplitManual`로 신규 거래를 순차 전송하고, 분할 거래 수정은 예상 버전·수정 요청 ID를 검사합니다. 마지막 온라인 인증 확인 후 30일이 지나면 재로그인이 필요합니다. 상세 범위는 [로컬 동기화 안내](local-sync.md)에 있습니다.

`/admin/register`의 분할 거래 링크는 `/admin/split`의 행 기반 입력 화면을 엽니다. 지출·수입·이체마다 2~50개 상대 계정 행을 만들고 금액 칸에서 사칙연산을 사용할 수 있습니다. 예산을 지정하는 지출은 모든 행에 예산 카테고리를 지정합니다. 등록 후 거래 목록의 수정 링크에서 날짜·메모·행을 수정할 수 있으며, 이전 버전을 `entry_revisions`에 남기고 버전 충돌을 거부합니다. 수정 권한은 작성자 또는 소유자에게 주며 계좌 쓰기 권한도 필요합니다. 카드 거래, 수신 승인 거래, 단순 거래는 이 수정 화면의 대상이 아닙니다.

카드 구매는 비용 차변/카드 부채 대변으로 즉시 기록합니다. 월별 할부 계획은 아직 확정 분개가 아닌 예정 데이터로 보관하고, 결제 시 카드 부채 차변/현금성 자산 대변으로 기록합니다. 누락 거래 일괄 조정은 모두 검증한 뒤 하나의 DB 트랜잭션으로 저장합니다. 보고서는 확정 분개만 집계합니다.

`src/adjustments.js`와 `/admin/adjustments`는 소유자 전용 누락 거래 일괄 조정과 역분개를 제공합니다. 한 배치에 1~50개의 두 계정 분개를 입력하며 각 금액에는 사칙연산을 사용할 수 있습니다. 온버짓 계좌 대변/비용 계정 차변인 행에는 예산 카테고리를 지정할 수 있습니다. 동일 제출 ID는 중복 저장하지 않고, 배치의 모든 분개를 하나의 SQLite 트랜잭션으로 저장합니다. 역분개는 원래 분개를 삭제하지 않고 차·대변을 바꾸고 예산 배분을 음수로 기록합니다. 하나의 배치는 한 번만 역분개할 수 있으며 날짜가 원래 조정일보다 빠를 수 없습니다. 역분개일이 다른 달이라면 예산 지출 취소가 그 달에 음수로 나타납니다.

`/admin/cards`에서는 카드 구매·할부 예정일 입력, 조회 종료일까지의 월별·회차별 미결제 금액, 실제 결제 기록을 제공합니다. 구매·결제에는 해당 카드 쓰기 권한이 필요하고 실제 결제에는 출금 계좌 쓰기 권한도 필요합니다. 구매 요청 ID는 중복 저장을 막습니다. 예정액은 확정 분개와 분리하고 결제 완료 회차는 미결제 목록에서 제외합니다. 2~100회차를 선택해 공통 출금 계좌·결제일로 묶음 납부를 기록할 수 있습니다. 회차별 분개 연결을 남기고, 모든 결제와 묶음 요청 이력을 한 트랜잭션에 저장하며 재전송을 중복 처리하지 않습니다. 카드사 청구 마감일 자동 계산은 아직 지원하지 않습니다.

`src/forecast.js`는 소유자 전용 예정 입출금(단건 또는 매월)을 `cash_schedules`에 저장합니다. `/admin/forecast`에서 기준일의 실제 현금 잔액부터 등록 일정, 미결제 카드 회차, 이미 기록한 미래 날짜의 현금 거래를 일자순으로 합산합니다. 카드 회차는 사용자가 선택한 현금성 출금 계좌에 예상 지출로 반영합니다. 시뮬레이션 금액 변경은 조회에만 적용하고 저장하지 않습니다. 예정 거래는 원장의 확정 거래가 아니며 기간은 최대 10년입니다. 원장에 별도 미래 거래로 같은 일정을 입력한 경우 해당 회차를 연결하거나 일정을 중지해야 중복 집계를 피할 수 있습니다.

예정 거래를 수정하거나 중지할 수 있고, 각 회차를 같은 현금 계좌의 동일 금액 실제 거래에 연결할 수 있습니다. 실제 날짜는 예정일의 앞뒤 31일 안에 있어야 합니다. 연결한 회차는 예상 일정에서 제외되고, 실제 거래가 예상 잔액에 반영됩니다. 실제 거래가 수정되어 금액이 달라지거나 예정 조건이 변경되면 연결을 검증하지 못하므로 해당 회차가 다시 예상 일정에 포함됩니다. 연결 내역에서 직접 해제할 수 있습니다. 한 실제 거래는 한 예정 회차에만 연결됩니다.

## 사용 예시

```js
import { Book } from './src/book.js';

const book = new Book('./budget.sqlite');
book.createAccount({ id: 'bank', name: '보통예금', type: 'asset', cash: true });
book.createAccount({ id: 'card', name: '신용카드', type: 'liability', card: true });
book.createAccount({ id: 'food', name: '식비', type: 'expense' });
book.cardPurchase({ id: 'purchase-1', date: '2026-10-10', cardId: 'card',
  expenseId: 'food', amount: 120000, count: 3, firstDueDate: '2026-11-25' });
console.log(book.pendingCardPayments('2027-01-31'));
book.close();
```

소유자는 월별 예산 화면에서 같은 달의 두 카테고리 사이에 배정액을 옮길 수 있습니다. 보내는 항목의 이번 달 배정액을 초과할 수 없으며, 총 배정액·지출·이월액·실제 원장에는 영향을 주지 않습니다. 이동은 두 배정액과 이력을 한 DB 트랜잭션에 저장하고 요청 ID로 재전송을 중복 처리하지 않습니다. 최근 20개 이동 기록을 표시합니다.

월별 예산은 카테고리별 매월 배정 목표를 지원합니다. 목표는 현재 설정을 모든 월 조회에 적용하며 저장된 월별 배정액을 자동 변경하지 않습니다. 부족액은 목표에서 이번 달 배정액을 뺀 양수 값으로 계산하고, 이월액·지출은 포함하지 않습니다. 소유자가 부족액 채우기를 실행하면 목표보다 적게 배정한 항목만 올립니다. 화면에는 필요한 합계와 적용 후 미배정 자금을 표시합니다. 0원 목표는 해제이며, 같은 요청의 재전송은 이후 사용자가 수정한 배정액을 다시 바꾸지 않습니다.

## 현재 제약과 다음 작업

- 계정별 재무상태표·손익계산서와 현금성 계좌 증감표 및 원거래 조회를 제공합니다. 현금 입출금은 영업·투자·재무 활동으로 분류하며, 소유자는 기간별 현금 입출금 및 계정별 차변·대변 내역을 CSV로 내려받을 수 있습니다. CSV의 사용자 입력 문자열은 스프레드시트 수식으로 실행되지 않도록 처리합니다. 일괄 조정은 별도 화면에서 제공합니다.
- 카드사별 이용 기간, 휴일 이월, 수수료, 부분취소·조기상환·일부 납부는 구현 전입니다. 첫 청구일을 직접 지정합니다.
- 가계부/가족별 **독립 장부** 격리는 아직 없습니다. Pocket ID 로그인은 등록한 가족 구성원에게 허용하며 계좌별 권한을 적용합니다. 모든 집계에 개인 계좌를 안전하게 숨기는 기능은 아직 제공하지 않습니다. 단축어는 API 키와 계정 키를 함께 사용합니다. HTTPS 프록시와 네트워크 접근 제한 아래에서 운영해야 합니다.
- 계좌 그룹·온/오프 버짓과 기본 예산 계산·월별 배정 UI를 제공합니다. 소유자는 계좌 관리에서 그룹 이름을 변경하고 같은 유형의 그룹으로 계좌를 이동하거나 그룹에서 제외할 수 있습니다. 그룹 변경은 원장 잔액과 예산 설정을 유지합니다. 월별 예산 화면에서 이전 달 배정액을 복사할 수 있으며, 이번 달에 이미 입력한 항목은 0원도 보존합니다. 복사는 아직 배정하지 않은 항목만 채우며, 이월 잔액이나 지출을 복사하지 않습니다. 월 배정 목표와 같은 달의 카테고리 간 이동을 제공합니다. 계좌 상태 변경 시 사전 영향 표시, 수입 카테고리, 저축 잔액 목표와 월간 배정 이동은 아직 구현되지 않았습니다.
- 분할 거래 표는 Tab으로 입력칸 이동, Enter/Shift+Enter로 같은 열의 아래/위 행 이동, 마지막 행에서 Enter로 행 추가, Ctrl+Enter 또는 ⌘+Enter로 저장을 지원합니다. 탭으로 구분한 상대 계정·금액 식·예산 카테고리를 2~50행 붙여넣어 현재 표를 교체할 수 있습니다. 오류가 있으면 기존 표를 보존합니다. 카드 할부 입력·예정액·회차별 지급 UI도 제공합니다. 임의 셀 범위 편집, 단순·카드·수신 거래의 수정과 거래 대사는 아직 없습니다.

- 거래 목록은 전체·미확인·확인 완료 상태, 시작일·종료일(양끝 포함), 메모 부분검색(대소문자 무시)을 제공합니다. 조건 적용 후 최신순으로 200건씩 페이지 이동하며 검색 거래의 증감 합계를 표시합니다. 잔액과 각 행의 누적 잔액은 전체 원장 기준을 유지합니다. 확인 처리 후에도 검색 조건과 페이지를 유지하고, 마지막 페이지가 사라지면 남은 마지막 페이지로 이동합니다. 미확인 거래를 선택해 한 번에 확인할 수 있습니다. 일괄 확인은 1~200개의 중복 없는 거래만 허용하고, 한 거래라도 변경되었거나 대상 계좌 거래가 아니면 전체 확인을 취소합니다.
- 비교 이력이 저장 당시와 동일하고 잔액 차이가 0원이며 미확인 거래가 없으면 쓰기 권한을 가진 구성원이 검토 완료로 표시할 수 있습니다. 완료자와 UTC 완료 시각을 별도 저장하고 반복 제출 시 최초 완료 기록을 보존합니다. 변경된 이력이나 미확인·차이 금액이 있는 이력은 완료할 수 없습니다. 완료 후 기준일 이내 거래 또는 확인 상태가 변경되면 재검토 필요로 표시하고 당시 비교 값·완료 기록은 보존합니다. 검토 완료는 원장을 잠그거나 자동 조정하지 않습니다.
