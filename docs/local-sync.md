# PWA 로컬 거래 입력 시제품

`/app/`은 브라우저 설치형 가계부의 첫 번째 범위입니다. 온라인 Pocket ID 로그인이 필요하고, 같은 브라우저 프로필에는 한 사용자만 로컬 자료를 저장합니다. 로컬 자료가 있으면 기기 잠금 암호를 입력해야 열 수 있습니다. 잊은 잠금 암호는 복구할 수 없으므로 전송되지 않은 거래는 사라질 수 있습니다.

## 데이터 흐름

1. 로그인 상태에서 `/app/`을 열면 `GET /api/v1/local/state`로 사용자 식별자, 접근 가능한 계좌 잔액·계좌별 최근 100건의 원거래, 상대 계정·예산 카테고리와 세션 CSRF 값을 받습니다. 입력 화면에서는 선택한 계좌의 최근 40건을 표시합니다. 분할 거래는 작성자 또는 소유자이며 쓰기 권한이 있는 경우에만 수정용 행·버전 정보를 내려줍니다.
2. 사용자가 8자 이상의 **기기 전용 잠금 암호**를 설정합니다. 계좌 스냅샷, 마지막 온라인 확인 시각, 전송 대기 거래는 Web Crypto PBKDF2(SHA-256, 310,000회)로 파생한 AES-GCM 키로 암호화하여 IndexedDB에 저장합니다. 암호나 암호화 키는 저장하지 않습니다. 데이터의 세부 내용은 서비스 워커 캐시에 넣지 않습니다.
3. 오프라인에서는 마지막 온라인 인증 확인 시점으로부터 최대 30일까지 잠금 암호로 자료를 열어 단순 지출·수입·이체와 2~50개 행의 분할 거래를 대기열에 추가할 수 있습니다. 분할 거래의 각 행에 상대 계정·금액 사칙연산·온버짓 지출 예산 카테고리를 지정할 수 있습니다. 대기열은 **원장 잔액에 반영되지 않습니다**.
4. 서버 연결 후 `POST /api/v1/local/transactions`로 차례로 보냅니다. 서버가 기존 계좌 권한·중복 제출 ID·CSRF 값을 확인한 뒤 단순 거래는 `recordManual`, 분할 거래는 `recordSplitManual`로 원장에 기록합니다. 분할 거래의 행과 예산 배분은 서버가 다시 검증합니다. 실패한 거래는 대기열에 남고, 사용자는 이를 삭제하고 새로 입력할 수 있습니다. 성공한 거래가 다시 전송되더라도 동일 요청 ID는 중복 분개를 만들지 않습니다. 이후 최신 스냅샷을 가져옵니다.

수정 가능한 기존 분할 거래는 로컬에서 날짜·유형·메모·상대 계정과 금액을 변경해 대기열에 저장합니다. 서버는 원거래의 예상 버전을 검사하여 다른 곳에서 먼저 수정했다면 `409`를 반환합니다. 대기열을 자동 삭제하거나 덮어쓰지 않습니다. 사용자에게 최신 거래를 확인하고 실패한 요청을 지운 뒤 다시 수정하도록 안내합니다. 수정 요청 ID와 결과 버전은 서버에 별도로 저장하여 응답 유실 후 같은 요청을 다시 보내도 원장을 두 번 수정하지 않습니다.

PWA 서비스 워커는 앱 화면·스크립트·아이콘만 캐시에 저장합니다. 사용자별 API 응답과 관리자 화면은 캐시에 저장하지 않습니다. 설치와 서비스 워커에는 HTTPS 또는 브라우저가 허용하는 로컬 보안 문맥이 필요합니다.

## 계좌 기간 잠금

계좌와 쓰기 가능한 이체 상대 계좌의 잠금 기준일을 스냅샷에 포함합니다. 최근 거래가 잠긴 계좌를 포함하면 수정 버튼을 제공하지 않습니다. 입력 시 원계좌·상대 계좌·분할 행의 잠금 기간을 검사하여 안내합니다. 이는 마지막 동기화 시점의 상태이며 서버의 현재 잠금 검사가 최종 기준입니다. 오래된 스냅샷에는 잠금 정보가 없을 수 있으므로 서버가 다시 검증합니다.

전송 시 잠금에 걸리면 서버는 `423`과 `PERIOD_LOCKED`를 반환합니다. 대기 거래와 오류 안내를 암호화해 보존하며 이후 거래의 전송도 보류합니다. 신규 거래는 실제 거래일을 확인한 뒤 대기열에서 날짜를 수정할 수 있습니다. 잠금으로 확실히 거절된 요청만 새 요청 ID로 바꾸며 금액·계좌·분할 행은 유지합니다. 기존 분할 거래 수정은 원거래가 잠겼을 수 있으므로 날짜 수정으로 우회하지 않고 소유자에게 잠금 해제를 요청하거나 대기 요청을 삭제하도록 안내합니다. 날짜를 임의로 미래로 옮겨 기록하지 않도록 실제 거래일 확인을 명시합니다.

재시도 직전에는 이전 잠금 오류 표시를 지우고 저장한 뒤 서버에 보냅니다. 응답 유실로 처리 여부가 불명확해진 요청에는 날짜 수정 기능을 제공하지 않으며, 동일 요청 ID로 재시도하여 서버가 중복 여부를 확인합니다. 이전에 성공한 요청을 잠금 후 다시 전송해도 새 분개를 만들지 않습니다. 신규 모듈을 오프라인에서 사용하도록 서비스 워커 캐시 버전을 갱신했습니다.

## 현재 범위

- 단순 지출·수입·이체, 다중 행 분할 거래 및 기존 분할 거래 수정을 오프라인 대기열에 저장합니다. 카드 구매·결제, 예정 거래, 예산 변경, 보고서, 전체 원거래와 계좌 수정은 서버 화면에서 사용합니다. PWA의 최근 거래 내역과 잔액은 마지막 서버 동기화 시점의 읽기용 복사본입니다.
- 서버가 받은 거래의 수정·삭제·충돌 자동 병합은 아직 없습니다. 서버에서 권한이나 계좌가 바뀌면 대기 거래가 거절될 수 있습니다.
- 기기 자료의 보안은 브라우저 프로필, 기기 잠금 및 별도 잠금 암호에 의존합니다. 같은 브라우저 프로필을 가족이 공유할 때는 로컬 저장소가 사용자마다 분리되지 않습니다.
- 실제 모바일 브라우저의 설치·장시간 오프라인 동작과 Pocket ID 연동은 추후 실환경 테스트에서 검증합니다.
