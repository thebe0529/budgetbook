# Actual CSV 거래 가져오기

수신 거래 검토 화면의 **Actual CSV 가져오기**에서 사용합니다. 현재는 계좌 하나의 단순 수입·지출을 검토함으로 가져오는 기능입니다. 예산·계좌·카테고리·분할·이체·초기잔액·카드 납부·환불을 포함한 전체 장부 이관은 지원하지 않습니다.

## 사용 순서

1. Actual에서 대상 계좌의 단순 수입·지출만 CSV로 내보냅니다.
2. `/admin/actual-csv`에서 BudgetBook 대상 계좌를 직접 선택하고 CSV 내용을 붙여넣습니다.
3. 미리보기에서 원래 계좌명과 대상 계좌, 날짜·금액·거래처·메모·카테고리 및 수입/지출 합계를 대조합니다.
4. 단순 거래와 대상 계좌·금액 단위를 확인하고 **검토함에 가져오기**를 누릅니다. 유사 기록이 있으면 별개 거래라는 추가 확인이 필요합니다.
5. 검토함에서 상대 계정과 예산 카테고리를 직접 지정하고 건별로 승인합니다. 가져오기만으로 원장·잔액·예산은 바뀌지 않습니다.

## 지원 형식

UTF-8 CSV 내용을 최대 100,000바이트·200거래·40열까지 받습니다. 쉼표 구분, LF/CRLF/CR 줄바꿈, BOM, 인용부호 안의 쉼표·줄바꿈, 이중 인용부호를 지원합니다. 열 이름은 대소문자를 구분하지 않으며 중복 열 이름은 거부합니다.

| 열 | 처리 |
| --- | --- |
| Date | 필수. 실제 날짜인 YYYY-MM-DD |
| Amount | 필수. 원 단위 정수. 음수는 지출, 양수는 수입. `1000.00`은 1,000원이며 100을 곱하지 않음. 소수 원·0원·수식은 거부 |
| Account | 선택. 있으면 모든 거래에 같은 계좌명이 있어야 함. BudgetBook 계좌에 자동 연결하지 않음 |
| Payee, Notes | 거래처·메모 원문을 보존하고 승인 입력에 함께 제공. 각 500자 이하 |
| Category | 원래 카테고리 참고 정보만 보존. 자동 생성·연결하지 않음 |
| Cleared, Reconciled | 원래 확인 상태를 참고 정보로 보존. BudgetBook 거래 확인·기간 잠금으로 승계하지 않음 |

다른 열은 거래 자동 매핑에 사용하지 않습니다. 분할을 나타내는 Notes의 `(SPLIT ...)`, ParentId/IsParent/IsChild 또는 0이 아닌 Split_Amount는 거부합니다. `Transfer:`/`이체:` 거래처 표시도 거부하지만 이름만 있는 이체를 완전히 식별할 수는 없습니다. 사용자가 단순 거래만 선택했다는 확인이 필요합니다. 부채 계좌의 양수 금액은 납부·환불 흐름이 필요하므로 거부합니다. 초기잔액·환불을 수입으로 승인하지 않도록 주의하세요.

## 중복과 검토

동일 대상 계좌에 같은 거래 묶음을 다시 가져오면 기존 검토 거래를 반환합니다. BOM·레코드 줄바꿈·열/거래 순서·정수 금액의 `.00` 표기 차이는 같은 묶음으로 처리합니다. 같은 파일 안의 날짜·금액·거래처·메모가 모두 같은 복수 거래도 건수를 보존합니다.

서로 다른 묶음에 기존 CSV 수신 내역과 날짜·금액·거래처·메모가 같은 행이 있으면 유사 기록으로 표시하고 명시적 확인 없이는 저장하지 않습니다. 확인 후에는 별개 거래로 모두 추가합니다. 승인 완료된 CSV 거래도 이 검사에 포함합니다. 원래 카테고리나 확인 상태를 바꾼 파일도 새 묶음으로 판정될 수 있습니다. 이 검사는 CSV 수신 내역 사이에만 적용되며 앱 푸시·수동 입력 등 다른 출처와의 유사 거래 매칭은 후속 범위입니다.

원래 카테고리와 확인 상태를 포함한 행 정보, 원래 계좌명·가져온 작업자·수신 시각·묶음 ID·검토 거래 ID를 보존합니다. 승인 후 같은 묶음을 다시 가져와도 원장을 다시 생성하지 않습니다.

## 권한·오류 처리

현재 대상 계좌의 쓰기 권한이 필요합니다. 조회 권한만 있는 사용자는 들어온 검토 거래를 볼 수 있으나 가져오기·승인은 할 수 없습니다. 계좌 권한을 회수하면 미리보기·가져오기와 검토 조회를 차단합니다. 두 POST 경로는 CSRF를 검증하고 저장 시 미리보기 지문을 다시 검사합니다. 파일 오류가 한 건이라도 있으면 전체를 거부합니다. 모든 수신 거래·묶음·요청 이력은 한 트랜잭션으로 저장하고 실패는 전체 롤백합니다. 재시작 후에도 중복 방지를 유지합니다.

100 KB 원문을 URL 인코딩해 전달할 수 있도록 CSV POST만 최대 1 MiB 폼을 허용합니다. 다른 관리자 폼의 16 KiB 제한은 유지합니다. CSV 셀은 텍스트/정수로만 해석하며 실행하지 않고 화면 출력은 HTML 이스케이프합니다.

기존 검토 승인에서 복식부기·현재 계좌 권한·예산 배분·기간 잠금 규칙을 적용합니다. 잠금 기간의 거래는 검토함에 보존할 수 있어도 원장 승인은 차단될 수 있습니다.

형식 확인에 사용한 공식 소스: [Actual CSV export implementation](https://github.com/actualbudget/actual/blob/master/packages/loot-core/src/server/transactions/export/export-to-csv.ts). 이 문서의 범위는 BudgetBook의 지원 계약이며 Actual 전체 내보내기 형식 호환을 뜻하지 않습니다.
